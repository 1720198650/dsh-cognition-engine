## 十三、资料层：收件从「待审」改成「自动学」（2026-11-18）
**起因**：用户当场质问「收件如果不能放进去自动学习，我为什么不直接在对话框发给你」。
查代码确认收件是残的：`inbox.accept()` 落的记忆正文是 `cand.summary`，也就是**前 200 字**，
一篇 2 万字论文采用后其余 19800 字直接蒸发。

**分层决定**（不再改）：论文/文档**不进记忆事实**，进资料层。理由是事实层参与每轮注入与
冲突仲裁，几十条同主题事实会把用户真实口径挤出检索窗口（记忆洪泛）。资料层不占每轮注入，
用到时才取——「学到」= 随时能查，不是「永远摆在眼前」。

| 件 | 内容 | 状态 |
|---|---|---|
| `src/source_library.ts` | 切块（空行分段 + 长段按句切，目标 600/上限 1200）+ `cognition-source-blocks.jsonl` + bigram/整词打分检索 + 输出按正文去重 | ✅ |
| `src/source_note.ts` | 提炼提示词（只送头 8000 + 尾 3000 字，标注中间省略）+ 严格 JSON 解析 + 失败兜底 | ✅ |
| 自动管道 | 三个入口（粘贴 / 按路径 / 浏览器选文件）都走 `ingestSource()`：先切块（同步、不依赖模型），再后台提炼（要模型） | ✅ |
| 新工具 `cognition_source` | 模型在对话里按需取回资料原文 + 摘要；与 `cognition_recall` 分工（口径 vs 资料） | ✅ |
| 路由 | `/sources/search`、`/sources/notes`、`/sources/redistill` | ✅ |
| 面板 | 收件页显示「已切 N 块 · 提炼状态 · 摘要 · 结论」、资料检索框、「重新提炼」按钮 | ✅ |
| 单测 | 235 全绿（切块不丢字、索引幂等、英文整词打分、解析挑剔、头尾截断） | ✅ |

**离线实测**（真实账本 `cognition-sources.jsonl`，10 条来源）：2 万字论文 → 33 块，
min 183 / avg 580 / max 1166；`memory organization`、`LoCoMo benchmark`、`bounded core`
都能命中正确段落；`ablative` 这类英文词不再被 bigram 噪声凑成 1.00。

**代价**：每篇导入多一次模型调用（约 2 万字符输入 / ≤2000 输出），记在 `/usage` 的 `source` 用途下。
模型不可用时不阻断导入：块索引照建、摘要标 failed、面板给「重新提炼」按钮。

**同日补测后追加**（用户放了长文/网页/表格/短文本四项）：

| 件 | 结论 |
|---|---|
| 表格按行数放开提炼（≥20 行，不受 800 字门槛） | ✅ 573 字统计表提炼出 5 条带真实数字的结论 |
| 自动判编码（BOM / UTF-8 严格 / GBK 兜底） | ✅ 946 字节 GBK 表正确读成「指标,本期值,同比」 |
| 表格按整行切 + 每块重复表头 | ✅ 40 行表 → 2 块，行数 33/9 不丢不重 |
| 检索跳过"整块只有一行路径"的块 | ✅ 修前「固定资产投资」第一名是 26 字路径，修后是真表格 |
| 资料删除（只删块+摘要，账本不动） | ✅ 面板「删」两步确认；删完块为 0 的行不再显示 |
| 坏行只跳过不 break + 删除前重读磁盘 | ✅ 修掉"删除连带抹掉别的资料 15 块"的数据丢失 |

**L0 是否算完成**：算。但要区分——完成的是「收件箱 + 资料层」，原来那条
"你能稳定每天审几条"的经验门槛随改版作废；现在的门槛是**资料形态覆盖**（见 l0-inbox.md 第八节）。
