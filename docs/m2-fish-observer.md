# M2：只读观察 dsh-fish（哈希锚 + 统计）

> 2026-11-16。工具：`scripts/fish-observe.mjs`。**只读，不写对方目录，不改对方行为。**

## 一、它解决什么

dsh-fish 的事件流（`~/.dsh-fish/events.jsonl`）是 append-only，但"不可改"只是**约定**——
没看到哈希链，也没有可校验的完整性证明。我们要做的不是替它改，而是**给它做体检**：

1. **哈希锚**：从第一条到第 N 条算一条独立哈希链，得到一个 head。
   把 head 记在别处（`--anchor-out`），下次比对就知道"这段历史有没有被改过"。
2. **统计**：事件量、时间跨度、**沉默天数**、类型分布、**重复率**。
   用来判断"她到底在长，还是在原地打转"。

## 二、用法

```powershell
# 默认读 ~/.dsh-fish
node scripts/fish-observe.mjs

# 指定目录 / 输出 JSON / 留锚点（锚点写到别处，绝不写进它目录）
node scripts/fish-observe.mjs --dir "C:\Users\你\.dsh-fish" --json --anchor-out D:\dshgz\_work\fish-anchor.json
```

## 三、实测输出（合成样本）

```
观察目录：...\fish-fixture
事件：6 条（可解析 5，坏行 1）
哈希锚：43e36c71d739051e…（长度 6）
时间跨度：2026-11-10 → 2026-11-13，共 4 天，空白 1 天
类型分布：wake=2  judgement=2  refuse=1
重复：1 段文本重复出现，冗余 1 条（20.0%）
```

## 四、能证明与不能证明

| 能 | 不能 |
|---|---|
| 这段历史自锚点之后没被改过（字节级） | 对方的判断对不对（语义问题，哈希管不了） |
| 事件量/沉默率/重复率的客观数字 | 她的"人格"是否成立 |
| 对方的事件流是否在空转（大量重复、长时间无事件） | 对方的记忆有没有失真 |

**说清楚**：我们不是去证明 dsh-fish 不好。它做了很多我们没做的事（B 站、日记、主动性、
四个成长阶段）。我们只是提供它没有的那一层——**可校验性**。这也是我们唯一的差异化。

## 五、字段识别（不猜 schema）

常见候选逐个试，识别不到就跳过并在报告里说明：

- 时间：`ts / at / time / createdAt / timestamp / date`
- 类型：`kind / type / event / op / action / name`
- 正文：`content / text / body / message / summary / judgement`

这样它对**任何 event-sourced agent** 都能用，不绑死 dsh-fish。

## 六、边界（红线）

1. 不写对方目录任何文件；`--anchor-out` 必须指到别处。
2. 不调用对方接口、不注入、不改它的配置。
3. 坏行只计数不丢弃（append-only 的流里出现坏行本身就是信号）。
