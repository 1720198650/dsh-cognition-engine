# 学习笔记：SoMem — Can LLM Agents Organize Their Own Memory?（arXiv:2611.11929）

> 2026-11-17。City University of Hong Kong + Tencent Jarvis Lab，2026-11-09。代码：[Qi202/SoMem](https://github.com/Qi202/SoMem)。

## 一、它做了什么（一句话）

**让 agent 用普通 Markdown 文档自己组织记忆，而运行时只负责三件事：校验编辑、派生视图、保持证据可追。**

## 二、结构（四个对象）

| 对象 | 是什么 | 我们的对应 |
|---|---|---|
| **Source** | 原始交互记录，**只追加、不可变** | 我们的 `cognition-state.json` 事实（append + 双时态） |
| **Topic** | agent 自己写/改的 Markdown 主题页 | 我们的 `wiki/<topicId>.md` |
| **Core** | **大小受限**的一段 Markdown，放进**每轮初始上下文** | 我们的注入段（但有预算，没有"Core 文档"概念） |
| **Graph / Timeline / Recent** | **从 Topic 自动派生**的三种视图，不单独维护 | 我们只有主题归属，没有时间视图/关系视图 |

关键设计：`Topic = 不变量`，三种视图都是**推导出来的**（`Graph(T)`、`Timeline(T)`、`Recent_K(T)`）。
好处：改一处 Topic，所有视图自动一致——**不用模型维护四份表示**。

## 三、段落 = 记忆单元（这条最值得抄）

每个段落 `u_i = (b_i, c_i, E_i, L_i)`：

- `b_i` 稳定段落 id
- `c_i` 段落文字
- `E_i` = 一组**证据标注**：`{陈述片段 s_ij, 事件时间 τ_ij, 来源引用 R_ij}`
- `L_i` 指向其他段落的引用

也就是说：**每一句陈述都挂着自己的时间和出处**，而不是整段一个出处。

## 四、更新流程（这才是核心）

```
模型提交修改（可以先改多个段落/文档）
  → 运行时校验：Source 不可变？文档结构合法？证据引用都能解析？
  → 通过 → 安装并重建视图
  → 不通过 → 拒绝，**原记忆状态保持不变**
```

对比我们：我们有 `editedSections` 保护（人工改过的不覆盖），但**没有结构校验**（引用是否可解析、层级是否合法）。

## 五、检索

工具只有三个：`Search`（BM25 或向量，可带路径/日期过滤）、`List`、`Read`（可读行区间）。
初始上下文 = **Core + Recent + 文件清单**；然后 agent 自己决定再搜什么、读哪段、回到哪条 Source。

## 六、结果（都是原文数字）

| 基准 | SoMem | 最强基线 | 差 |
|---|---|---|---|
| LoCoMo overall | **88.96** | E-mem 86.30 | +2.66 |
| BEAM-100K | — | — | +3.10 |
| LongMemEval-S | — | — | +2.00 |

**但必须注意一行**：**Full Context（全量上下文）在 LoCoMo 是 84.22**，SoMem 88.96 只比它高 4.7 个点。
→ **记忆系统的对手是"全量塞进去"，不是"不记忆"**。这条对我们是警示，见 §八。

## 七、能直接改我们代码的三条

### 1. Core 文档（常驻、限长、独立于注入预算）
我们现在的注入是从准则/记忆现拼的，没有"一段稳定的 Core"。
**做法**：新增 `core.md`（≤60 行），从 wiki/准则里提炼"长期偏好 + 常驻要求"；每轮放在注入最前面，其余照旧。
**收益**：跨会话身份稳定，且**可被别的模型复用**（它证明了这点）。

### 2. 段落级"时间 + 多来源"标注
我们现在 wiki 每条只带一个 `[fact-id]`。
**做法**：改成一个 bullet 可以带 `（2026-10~今；mem-7, mem-17）`——时间窗 + 多条来源。
**收益**：时间类问题能直接答，不用再回查；也方便判断"这条是不是过期了"。

### 3. 保存前结构校验（这是最该补的）
我们现在 `/wiki/save` 只检查长度。
**做法**：保存前校验三件事——① 每个 `[fact-id]` 都真实存在；② 标题层级合法（不跳级）；③ 时间标注格式合法。任一不过 → 拒收并说明，**不改旧文件**。
**收益**：模型手滑改坏记忆的概率直接归零；这是它比我们强的地方。

## 八、它的局限 / 对我们最重要的警示

1. **对手是全量上下文**：SoMem 88.96 vs Full Context 84.22。差距不大。
   → 我们的 **index-only 注入（348 字）很可能打不过全量**。所以**别自嗨**：必须做消融，证明"少了那 348 字会更差"，否则我们只是省了 token、没变好。
2. **成本在输入上下文**：附录 D 明说成本集中在可复用的输入上下文（Core + Recent + 清单），不是模型调用。
3. **它用 GPT-6 Luna 当 Reader**：我们的宿主模型不同，绝对分数不可移植，只能比"相对增益"。
4. **它没解决"人格/倾向"**：只解决记忆组织。我们的沉积层它没有，别指望它给答案。

## 九、能不能直接下载粘贴到收件？

- **PDF：不行**——二进制，收件只收纯文本（会拒收）。
- **HTML：可以**——在 arxiv 页面点 `HTML (experimental)`，另存为 `.html`，收件里填路径导入；我们的抽取层会剥掉标签。
- **最省事**：直接选中正文复制，粘到「收件」的文本框。
