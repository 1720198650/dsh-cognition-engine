# P5：任务简报（确定性版）

> 2026-11-17。模块：`src/brief.ts`；路由 `POST /cognition-engine/brief?task=&completion=`；
> 命令行：`npm run brief -- "任务描述"`。
> **定位：给子代理 / 超级代理的工作集，不进主上下文。**

## 一、为什么放在这里（而概念层被 C0 挡下）

| | 主上下文注入 | 子代理 / 超级代理 |
|---|---|---|
| 上下文寿命 | 几十轮，长期 | **一次性，任务完就丢** |
| 需要概念稳定吗 | 需要（否则前后矛盾） | **不需要，当场够用即可** |
| 最缺什么 | 记忆与准则 | **一份能直接开工的简报** |

所以 C0 的失败（概念边界不稳）在这里不构成问题——**同一份数据，用途不同，要求就不同**。

## 二、结构（照 arXiv:2611.05306 附录 A 的"好压缩"四件套）

```
## 任务                ← 任务原文
## 完成判定            ← 什么算做完
## 相关事实            ← ≤8 条，每条带 [id]，可 recall 展开
## 适用准则            ← ≤3 条，带「不适用于」
## 该避开              ← 同主题已被推翻的旧口径
## 主题附注            ← wiki 摘录（可选）
## 提醒                ← 兜底/截断说明
```

**每条事实必须带 id**：不带 id 的简报无法核对，等于又编一遍。

## 三、选材规则（纯确定性，零模型）

1. **主题优先**：任务命中主题（名字或别名）→ 该主题的事实直接进候选（相关性按 ≥0.5 记）。
   理由：用户说"发版"，事实主题是"发版频率"，字面不像但意思就是相关。
2. **相关度**：其余按 `字二元组相似度 × 0.7 + 重要度 × 0.2` 排序，相关度 <0.15 的不要。
3. **没有相关事实时**：按重要度取 3 条，并**明确写"供参考，不是结论"**。
4. **准则只取有边界的**：没写"不适用于"的准则不进简报（否则会被无脑套用）。
5. **体积**：默认 ≤800 字。超了按顺序降级：去 wiki → 去"该避开" → 砍事实条数 → 最后才硬截断，并留一条说明。

## 四、实测（真实数据）

```
$ node scripts/task-brief.mjs "发布流程要做哪些事" --completion "六步全过"
→ 选入 3 条事实（mem-7 / mem-18 / mem-17），各自带 id，共 3xx 字
```

未命中主题时（如"发版前要做什么"）：只选中 mem-17，并提示"相关事实很少"——**它在说实话，不是说满**。

## 五、怎么用

| 场景 | 用法 |
|---|---|
| 派子代理 | 生成简报 → 粘进子代理任务的"背景"段（不是让它自己查） |
| 超级代理 | ticket 描述里带上简报；**worker 是 preset 作用域，拿不到我们的注入，简报是唯一通道** |
| 手工开工 | 自己先看一眼，确认它选的事实对不对 |

## 六、验收（下一步才做）

- **A/B 10 个真实任务**：有简报 vs 无简报 → 比"一次通过率"和"返工次数"；
- 简报 ≤800 字、每条带 id；
- **如果 A/B 没差别，判定简报是装饰，撤掉。**

## 七、局限

**选材靠检索。检索错了，简报就错。** 所以它必须把"选入了哪几条、score 多少"回传（`picked` 字段），
让人能看出它凭什么这么选——而不是只给一段漂亮的总结。
