# 概念层（Concept Layer）：用"一多关系"压缩上下文的可行性

> 2026-11-17。回应提问：反思引擎能不能承担上下文压缩？能不能像黑格尔（存在论/本质论/概念论）
> 和《巴门尼德篇》的"一多"那样，把上下文压成几个概念？
>
> **结论先说**：思路成立，但**不能用反思引擎去做压缩**。能做的是"概念层 + 指针"，
> 而且必须是**确定性构造、LLM 只负责起名**。理由见第三节。

---

## 一、先分清三件事

| 想法 | 判断 |
|---|---|
| 用**反思引擎**（三段式辩证）压缩上下文 | ❌ **不行**。见 §3 的三条硬伤 |
| 把上下文**抽象成概念**（一多关系） | ✅ 可行，而且有成熟理论：**形式概念分析（FCA）** |
| 用黑格尔三层做**分层命名** | 🟡 可以当设计语言，**不能当算法** |

## 二、相关项目与论文（都可查）

| 来源 | 对我们的用处 |
|---|---|
| **What to Keep, What to Forget: A Rate–Distortion View of Memory Compaction**（[arXiv:2607.08032](https://arxiv.org/abs/2607.08032)） | **最关键的警告**：所有 fold / prune / rewrite 都是**不可逆**的，"被认为不重要的细节就永远没了"。→ 概念层必须是**指针**，不能替代原文 |
| **Formal Concept Analysis 的增量算法**（FastAddIntent, 2015；分布式增量概念格, 2025） | "一多"的数学形态就是**概念格**：外延=多个对象，内涵=一组属性。而且**有增量算法**，契合我们"只追加"的事件流 |
| **hLDA / nested CRP**（Blei et al., 2003） | 分层主题：越上层越抽象。证明"层级"是有效结构，但我们只需要**两层**，不做无限层 |
| **LightOL**（IEEE, 2026） | 轻量本体学习：概念挖掘 + 属性生成 + 关系抽取的统一流水线，可作为属性抽取的参照 |
| **LLMLingua / LLMLingua-2**（[arXiv:2310.05736](https://arxiv.org/abs/2310.05736)） | token 级压缩能做到 5–20×，但**丢掉的东西找不回来**。我们不采用它当主路径，但可以当"最后 10% 预算不够时"的兜底 |
| **AutoCompressor**（EMNLP 2023） | 学出来的摘要向量。需要训练，我们不改模型 → 不采用 |
| **Concept Bottleneck Models**（[arXiv:2004.10943](https://arxiv.org/abs/2004.10943)） | 中间概念层可解释。但它服务分类任务，不是文本压缩；只借"中间层要人能看懂"这一点 |

## 三、为什么反思引擎不能干这活（三条硬伤）

1. **反思是生成式的，压缩必须是可复现的。**
   同一个上下文跑两次反思，输出可能不同 → 注入内容抖动 → 缓存失效、行为不可解释。
2. **反思每压一次就漂一次。**
   这正是 SSGM（arXiv:2603.11768）说的"反复摘要导致语义漂移"。我们自己的 wiki 都只做增量 patch、不做全量重写，压缩更不该交给生成模型。
3. **成本方向错了。**
   反思一次要 3 次模型调用；而压缩是**每轮都要发生**的事。用贵的机制处理高频操作，等于自杀。

**反思引擎该干什么**：检测矛盾、给裁决建议（它擅长）。**不该干什么**：当压缩器。

## 四、可行的设计：概念层（Concept Layer）

### 4.1 数据结构

```
概念 C-12
  name:        "发布流程·六步口径"        ← LLM 起名（可缓存，只在成员大改时重算）
  definition:  "发版必须六步，不可跳步"    ← LLM 一句话（≤40 字）
  members:     [mem-18, mem-7, mem-17, ...]  ← **指针，永远保留**
  attributes:  { 主题:发布流程, 时间窗:2026-10~今, 类型:结论 }
  contradictions: ["mem-1（旧四步口径，已失效）"]
  counts:      { members: 7, superseded: 2 }
```

**一** = 概念 + 内涵（属性）；**多** = members（事实 id）。

### 4.2 怎么造（确定性为主）

1. **属性抽取**（纯代码）：主题、时间窗、来源、重要性档、是否结论句、有无被取代。
2. **概念构造**：同主题 + 相同属性签名 → 一个概念；跨主题共享属性 → 上一级概念。**最多两层。**
3. **LLM 只做两件事**：起名、写一句定义（≤40 字）。**不许它决定成员归属**。
4. **增量**：新事实进来 → 按属性签名归到已有概念或新建；被取代的 → 从 members 移到 contradictions。

### 4.3 注入怎么用

```
[概念] 发布流程·六步口径（7 条，2026-10~今）｜发版必须六步不可跳步
[概念] 插件架构·零依赖（5 条）｜不得引入外部数据库
（需要细节时调 cognition_recall，按概念 id 展开全部成员事实）
```

- 每主题概念 **≤8 个**，全局 **≤40 个**
- 概念层总字符 **≤ 来源事实的 0.2×**（比 wiki 的 1.0× 更严）
- **任一概念必须能一键展开回全部成员事实**；展开是唯一的还原路径

### 4.4 验收（三条，缺一不可）

| # | 判据 | 测法 |
|---|---|---|
| A | **压缩率** | 注入 token 降到原来的 ≤1/3 |
| B | **不掉点** | 用固定探针问题集（20 条），准确率下降 ≤2 个点 |
| C | **可还原** | 随机抽 10 个概念，展开后能拿回原文；成员的 superseded 关系不丢 |

**任何一条不过就退回 index-only（现在已有）**——那个至少是安全的。

## 五、和黑格尔/巴门尼德的对应关系（说清楚，别神化）

| 哲学说法 | 工程对应 | 能不能用 |
|---|---|---|
| 存在论 → 本质论 → 概念论 | 原始事实 → 关系与矛盾 → 概念与类型 | ✅ 当**三层命名**用 |
| 一多关系（《巴门尼德篇》） | 概念格：内涵为一，外延为多 | ✅ **有数学对应（FCA）** |
| 辩证法的"扬弃" | 被取代的事实不删，标失效 | ✅ 我们已经在做（双时态） |
| "概念统摄一切" | 用几个抽象概念替代全部细节 | ❌ 这正是 rate–distortion 警告的不可逆丢失 |

## 六、里程碑

| 阶段 | 内容 | 工时 | 退出条件 |
|---|---|---|---|
| **C0** | 在现有 20 条真实记忆上，人工标 10 个"应该存在的概念" | 0.5 天 | 若人标不出稳定概念集合 → 停，说明数据还不够 |
| **C1** | 确定性概念构造 + LLM 起名；产出概念清单（只读，不注入） | 1 天 | 概念数 ≤ 40；成员归属可解释 |
| **C2** | 注入切换为"概念行 + 按需展开" | 1 天 | A/B/C 三条过 |
| **C3** | 与 wiki 合并展示（wiki 是主题的叙述，概念是跨主题的索引） | 0.5 天 | 不重复注入同一内容 |

**C0 是闸门**：如果连人都标不出一组稳定概念，说明我们现在数据量不足（20 条事实、3 个主题），
做出来必是拍脑袋——那就先别做，等观察期结束再说。

## 七、结论

- **反思引擎：不承担压缩。** 它是"矛盾检测器"，不是"压缩器"。
- **概念层：可行且有理论（FCA）**，但必须确定性构造 + 指针化 + 可展开。
- **"一多"这个直觉是对的**，它的工程形态就是概念格；但"剩下几个概念就够了"这个说法**必须加限定**：
  剩下的是**索引**，不是**内容**。内容永远在，只是不再每轮都塞进上下文。

## 八、"定子"论：概念层到底是什么（v1.1 补充）

> 用户的原话：LLM 本质是预测机器，把无限概念收束成有限概念，让概念当"定子"引导输出方向。

**对一半，而且是有用的那一半。** 但有三处必须修正，否则会误导实现。

### 8.1 三处修正

**① 收束 ≠ 模型只在有限概念里想。**
有限概念是对连续空间的**量化**，量化必然有损；能保证的只是"在你在意的维度上无损"，
而这要求先说清"在意什么"。给几个概念不会把模型的假设空间变成有限集，
只会给它的输出分布加一个**偏置**。

**② 真正的"定子"是改激活，我们够不到。**
这个隐喻在学术上有精确对应：

| 概念 | 出处 | 是什么 |
|---|---|---|
| **Conceptor（概念子）** | Jaeger, [arXiv:1403.3369](https://arxiv.org/abs/1403.3369) | 字面就是"概念 + 算子"：用神经滤波器把动力系统约束到子空间 |
| **Representation Engineering** | Zou et al., [arXiv:2310.01405](https://arxiv.org/abs/2310.01405) | 在表征层读出并操纵高层概念 |
| **Inference-Time Intervention / steering vectors** | Li et al., [arXiv:2306.03341](https://arxiv.org/abs/2306.03341) | 推理时加方向向量，直接改输出倾向 |
| **Concept Bottleneck Models** | [arXiv:2004.10943](https://arxiv.org/abs/2004.10943) | 中间概念层，可解释；服务分类不是文本压缩 |

这些都改模型内部。**我们是纯插件，碰不到权重**——只能做**文本定子**（prompt 级），
强度低一个量级，且跨上下文不稳。这个界限必须写死，不能拿"定子"把能力说大。

**③ 定子必须有刹车。**
预测机器 + 定子 = 正反馈回路：偏一点 → 输出更偏 → 下次定子跟着偏。
没有可核对信号校正，几轮之后无法解释它为什么这么说。
所以准则要证据、改口要日志、沉积层要哈希链——**这是刹车，不是装饰**。

### 8.2 定位

**概念层不是压缩器，是控制面（control surface）。**

```
概念（定子的文本形态） → 注入（有限/稳定/带指针） → 输出偏向这些概念 → 反馈回写
```

压缩是副产品，**控制才是目的**。这也解释了为什么概念必须带 `members` 指针：
定子只指方向、不承载内容；内容丢了就再也回不来。

### 8.3 必做实验：定子强度（Stator Strength）

无法区分"定子在工作"与"定子是装饰"的功能，不该存在。测量方法：

- 同一批 **20 个问题**，跑两组：**开概念层 / 关概念层**；
- 比三样：输出 embedding 距离、关键词命中率、**人类盲评**（你分不出哪组 = 无效）；
- **强度低于阈值 → 判定为装饰，不做这个功能。**

这条写进 C2 的验收，与"压缩率 / 不掉点 / 可还原"并列。
