## 一、先回答那个问题：分工，不是二选一

**判据不是"谁更聪明"，而是"这一环必须可复现吗"。**

| 环节 | 该用谁 | 为什么 |
|---|---|---|
| **这是不是一次翻案、翻得多重**（语义） | **LLM** | 要理解意思。正则必然错：我实测踩过——旧文本里的"改成"会污染后面每一条补充，把补充全判成翻案 |
| **加多少、夹在哪、链怎么接**（状态转移） | **确定性** | 必须可复现、可审计。LLM 做加法会漂移，重放结果不同，哈希链当场断 |
| **她怎么把这个变化说出来**（表达） | **LLM** | 这是体验层，本来就该是文本 |

### 依据（都是真的，能点开）

1. **Stechly, Valmeekam, Kambhampati, 2024**（[arXiv:2402.08115](https://arxiv.org/abs/2402.08115)）：
   让 GPT-4 自我批评，性能**显著崩塌**；换成 sound 外部验证器才有**显著增益**。
   → 自我判定不可靠，外部判定才是增益来源。
2. **Kambhampati et al., ICML 2024**（[arXiv:2402.01817](https://arxiv.org/abs/2402.01817)）：
   LLM 应被当作"通用近似知识源"，由**外部模型化验证器**做判定（LLM-Modulo）。
   → 这就是我们该有的形状：LLM 提判断，确定性装置判收不收。
3. **Zheng et al., 2023**（[arXiv:2306.05685](https://arxiv.org/abs/2306.05685)）：
   LLM-as-judge 有位置偏好、长度偏好、自我增强偏好。
   → 不能把 LLM 当唯一裁判，只能当"提证据的一方"。
4. **Park et al., 2023**（Generative Agents, UIST）：记忆流 + LLM 反思 + 按 recency/importance/relevance 检索。
   → 证明"叙事由 LLM 写"这条路能做出体验，但它的状态是文本，不可形式化审计。

### 一个工程硬约束（这条最要命）

**LLM 的判定必须冻结进事件，重放只读不重算。**

否则同一批事件重放两次，判定可能不同 → 哈希不同 → 链断 → "不可逆"这个卖点直接失效。

所以事件里要写：`judge: {verdict, tension, evidence, model, at}`。
`model` 记具体版本，将来统计"换模型后判定风格是否漂了"要分层看。

**判不出就 fail-closed：不写事件，不退回正则瞎猜。**

## 二、分工后的四层

```
① 表达层（文本）  LLM 写判断/日记/立场 —— 可有可无，可换模型，不影响下面
② 语义层（判定）  LLM 标注：这对事实是翻案吗？多强？依据哪两段原文？
                    ↓ 冻结进事件
③ 状态层（确定性）4 维 + 哈希链，只吃冻结的标注，永不重算
                    ↓ 只出三个数
④ 作用层（偏置）  改检索阈值/排序权重/注入权重 —— 不产出任何文本
```

**单向**：①③④ 互不回写。清空 ① 和 ②，③④ 仍然成立 —— 这就是非检索判据。

## 三、和 dsh-fish 怎么合

它的内核（读源码核实）：

- `events.js`：事件模板，只给处境不给台词
- `derive.js`：纯函数把事件流算成内部 `needs`（数值，不出现在给她看的文本里）
- `persona.js`：**把 needs 翻译成一段中文**，注入 system 段
- `recall.js`：她自己翻事件流（只读、封顶）
- 无 `createHash` —— "不可逆"是文档约定

**它的强项是 ①，我们的强项是 ②③④。** 融合方式：

| 它出 | 我们出 |
|---|---|
| 事件的叙事与台词 | 事件的**语义标注**（翻案/强度/依据） |
| 她的语气与态度文本 | 她的**起点偏置**（不写一个字） |
| 体验 | 可验证性 |

**不侵入**：我们用它的 `events.jsonl` 做只读输入，自己的状态落 `cognition-sediment.jsonl`，两套数据互不改写。

## 四、差异化落在三件具体的产出上

| 产出 | 是什么 | 别人有吗 |
|---|---|---|
| **哈希锚** | 给任何 events.jsonl 算一条链，证明"从第 N 条之后没被改过" | 没有（fish 靠约定） |
| **消融报告** | 清空最近记忆后，她还不同吗？差多少？ | 没有（fish 的成长就是文本，掐掉就没了） |
| **视角窗** | 她此刻会先看到什么 / 会忽略什么 / 什么姿态 | 没有 |

这三样都是**只读**的，装上不改变任何人的行为 —— 这是能被别的插件用户接受的前提。

## 五、里程碑

| 阶段 | 内容 | 工作量 | 退出条件 |
|---|---|---|---|
| **M0** | 标注器对照实验：50 对真实取代，人工标 30 条金标准，比「正则 vs LLM」准确率与假阳性 | 0.5 天 | **LLM 不比正则显著好 → 不做 M1，省下后面的活** |
| **M1** | 把 `judge` 接进 sediment：事件带冻结标注，重放不重算，链仍通 | 1 天 | 改一条 → brokenAt 精确；重放两次链相同 |
| **M2** | 只读观测器：读 `~/.dsh-fish/events.jsonl`，出哈希锚 + 统计（事件数/判断数/重复率/沉默率） | 1 天 | 不改对方任何文件；对方插件照常跑 |
| **M3** | 融合形态：她的叙事用 fish，起点用我们 | 2 天 | 消融后仍不同，才算成立 |

**M0 是闸门。** 如果 LLM 判定不比正则准，那就不该引入 LLM —— 多一次调用、多一个不确定源，买不到东西。

## 六、红线和风险

- 不因为"效果更好"去调 η、阈值、维度
- 不把 LLM 判定结果当事实写进记忆库（它只是"这一对是翻案"的标签）
- 不给对方插件改文件（M2 纯读）
- 成本：一次取代一次调用，可忽略；但要防"短时间大量取代"把调用打爆 → 每分钟上限
- 换模型后判定风格会变 → 事件里记 `model`，统计分层，不混算
