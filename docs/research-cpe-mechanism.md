# CPE（Capability-Preserving Evolution）机制拆解

> 来源：arXiv 2605.09315《Do Self-Evolving Agents Forget? Capability Degradation and Preservation in Lifelong LLM Agent Adaptation》（UIUC，2026-05）
> 目的：能不能在纯 JSON 插件里实现「学习不侵蚀旧能力」

---

## 一、核心定义

### 1.1 能力侵蚀的形式化

设智能体在生涯中遇到任务分布 `D1, D2, …, DT`，第 t 阶段的「能力状态」记为 `R_t`（可以是 workflow / skill 库 / 模型参数 / 记忆库）。

- 当前阶段损失：`L_t(R) = E_{x~Dt}[ℓ(R, x)]`
- 保留风险（对历史分布的加权）：`L_<t(R) = Σ_{i<t} α_i · L_i(R)`，`α_i ≥ 0`，`Σα_i = 1`

**定义（能力侵蚀）**：当

```
L_<t(R_t) > L_<t(R_{t-1})
```

即「为适应新任务做的更新，抬高了旧任务的风险」，就发生了能力侵蚀。

### 1.2 三种表现形式

| 形式 | 表现 |
|---|---|
| **回顾性能力衰减** | 在新分布上微调后，旧任务表现下降 |
| **行为策略漂移** | workflow 变长变复杂，引入多余步骤（噪声） |
| **泛化侵蚀** | 适应新分布会收窄有效推理空间，干扰旧能力 |

### 1.3 局部机理（Proposition 1）

设 `R_{t-1}` 是旧损失的局部极小，`H_<t = ∇²L_<t ⪰ 0`（旧任务曲率），`g_t = ∇L_t`（新任务梯度）。朴素更新 `R_t = R_{t-1} - η·g_t`，则

```
L_<t(R_t) − L_<t(R_{t-1}) = (η²/2)·g_tᵀ H_<t g_t + o(η²)
```

**结论：侵蚀不取决于更新有多大，而取决于更新方向是否落在「旧任务敏感的方向」上。**

## 二、CPE 的解法

### 2.1 加保留正则

```
R_t^CPE ∈ argmin_R  L_t(R) + λ·Ω_t(R, R_{t-1})
```

- `Ω_t` 度量「偏离既往能力支撑结构」的程度
- `λ > 0` 控制稳定性–可塑性权衡；`λ = 0` 就是朴素演化
- **`Ω_t` 不是阻止演化，而是把演化偏向「低干扰解」**

### 2.2 局部遗忘控制（Proposition 2）

在二次近似下：`Δ_λ = −(H_t + λ·M_t)^{-1} g_t`

其中 `M_t ≻ 0` 是保留度量。在假设 `H_<t ⪯ c·M_t`（保留度量能上界旧任务曲率）下：

```
L_<t(R_{t-1} + Δ_λ) − L_<t(R_{t-1}) ≤ (c / 2λ²)·‖g_t‖²_{M_t^{-1}} + o(‖Δ_λ‖²)
```

**直觉：λ 越大，旧任务退化被压得越狠，但同时新任务更新也被限制——这就是稳定性–可塑性权衡。**

### 2.3 四条通道的具体化

| 通道 | `R_t` | `Ω` 怎么做 |
|---|---|---|
| **Workflow** | 可执行 workflow / prompt program | 抑制偏离「既往成功执行行为」 |
| **Skill/Tool** | 有界技能库 | 抑制删除「既往有用的技能」 |
| **Model** | 参数 / adapter | `Ω = ½ Σ F_i (θ_i − θ_{t-1,i})²`（Fisher 式重要性加权） |
| **Memory** | 持久记忆库 | 抑制删除或压制「对旧分布有用的记忆」 |

## 三、我们的纯 JSON 实现

我们只有 **workflow（准则的 when 触发）**、**skill（procedure 准则）**、**memory（双时态记忆）** 三条通道，没有 model 通道。

### 3.1 对应关系

| 论文通道 | 我们 | `Ω` 的离散近似 |
|---|---|---|
| Workflow | 准则的 `when` + 步骤顺序 | 「旧 when 覆盖的场景，新准则不能让它失效」 |
| Skill | `kind: procedure` 的技能卡 | 「旧技能卡不能被新卡挤掉或删掉」 |
| Memory | 双时态记忆 | 「旧记忆的 `validTo` 不能无理由提前」 |
| Model | ❌ 无 | — |

### 3.2 可落地的最小 CPE：**回归集 + 变更闸门**

不需要 lambdas、Hessian；用**固定的旧任务回归集**近似 `L_<t`：

```json
{
  "cpe": {
    "holdout": {
      "caseIds": ["case-001", "case-002", "..."],
      "frozenAt": 1793790459061,
      "neverUsedForGeneration": true,
      "size": 50
    },
    "baseline": { "passRate": 0.92, "measuredAt": 1793790459061, "revision": 12 },
    "thresholds": { "maxDrop": 0.10, "minCases": 50 },
    "lastCheck": { "at": 0, "passRate": 0.0, "delta": 0.0, "action": "none" }
  }
}
```

**流程**：

1. 冻结 50–100 条「以前能做对」的任务，**永远不用于生成候选**（防止污染）
2. 每次准则/记忆变更后，跑一遍回归集
3. `passRate` 相对 `baseline` 下降 > `maxDrop` → **阻止变更**，回滚，记 incident
4. 通过则更新 baseline（用 EMA 平滑，避免噪声累积）

### 3.3 为什么这等价于 CPE

| 论文 | 我们的近似 |
|---|---|
| `L_<t(R)` 保留风险 | 回归集通过率（下降 = 风险上升） |
| `Ω_t` 保留正则 | 「变更后必须过回归集」的硬约束 |
| `λ` 稳定-可塑权衡 | `maxDrop` 阈值（越严越稳） |
| `M_t` 保留度量 | 回归集的覆盖广度 |

**差别**：论文是**软约束**（正则项），我们是**硬闸门**（不通过就不许改）。对小规模本地插件，硬闸门更简单也更安全。

### 3.4 与「skill 通道」对应的具体规则

借论文的 `Ω_sk`（抑制删除既往有用技能）：

- `kind: procedure` 的技能卡**不允许硬删除**，只能 `retired`（保留 + 不注入）
- 技能卡退役前，检查最近 90 天是否被 `appliedGood` 过；有 → 需要人工确认
- 这与我们已有的准则退役机制一致，只是把「禁止删除」写死

### 3.5 与「memory 通道」对应的具体规则

借论文的 `Ω_mem`（抑制删除对旧分布有用的记忆）：

- 记忆的 `validTo` 一旦设置，**不能被短期的「看起来没用了」自动提前**
- 衰减只影响排序，不影响 `validTo`（我们已这样做）
- 归档（archive）可以，但必须可恢复，且保留完整内容

## 四、验收标准

| 检查项 | 标准 |
|---|---|
| 回归集存在且冻结 | `cpe.holdout.frozenAt` 非空，`neverUsedForGeneration = true` |
| 每次变更都跑 | `lastCheck.at` ≥ 最后一次变更时间 |
| 阻断有效 | 人为制造一次性能下降，验证闸门能阻止 |
| 无静默通过 | 回归集通过率下降时，日志里有明确记录 |
| 覆盖广度 | 回归集覆盖所有 `topicIds` |

---

## 五、一句话

> **CPE 的论文版是「加一个正则项，让更新偏离旧任务敏感方向」；**
> **我们的版本是「加一个回归集，变更过不了就不许改」。**
>
> 数学不同，**效果相同**：都是让「学新的」不能「牺牲旧的」。
> 而且是**纯 JSON + 一次脚本运行**就能做的。
