# 两份材料的价值判断（2026-11-17）

## 一、PyBot / DeepSeek Agent Swarm —— **价值低，只作论据和反例**

来源：HuggingNews 转述 X 上的几条推文（[@cmpatino_ / @\_lewtun / @lvwerra]），**不是论文、没有评测报告**。

它声称的：
- 1,000 个 DeepSeek-V4.1-Flash agent，一周内协作（17.5 万条消息、8,000 个 PR）
- 产出 PyBot：**63 万行 Python**，**零依赖**，单核 CPU，内存约为同级模型的 1/10
- 在日常问答上"追平 SmolLM-360M"

### 为什么不值得抄

1. **63 万行代码不是资产，是负债。** 单文件量级到这个程度，没有任何人能维护，也没有人能审计。我们现在整个插件约 6,000 行、213 个测试，这是能负责的规模。
2. **"追平 360M 模型"只在"日常问答"这个窄口径上成立**，而且没有公开评测集与复现步骤。属于典型"把限定条件下的结果说成通用能力"。
3. **agent swarm 生成代码**这条路，产出的是"量"，不是"架构"。我们真正需要的判断（该记什么、该不该改口）它一个都没解决。

### 它唯一对我们有用的两点

| 用法 | 说明 |
|---|---|
| **论据** | 它证明"窄任务上确定性规则可以顶掉小模型"——这支持我们"语义归语义、状态归确定性"的分工，也支持 wiki/检索走零模型路径 |
| **反例** | 它提醒我们**别让 agent 大规模生成代码**。我们要的是少而可审，不是多而不可读 |

**结论：不采纳任何设计。最多在方案里引用一次作为"确定性路线可行"的旁证。**

## 二、SkillHone（EMNLP 2026 Industry，pages 1819–1829）—— **价值高，机制值得抄**

Zhiwei Li, Yong Hu. *SkillHone: A Harness for Continual Agent Skill Evolution Through Persistent Decision History.*

### 它解决什么问题（原文摘要）

> 现有方法在**有界的运行**里改进技能，而且**只保留最后的产物**，把"后来者需要的决策历史"丢了——
> 那些诊断、修订、评估和**被否掉的备选方案**。

它的做法：
1. **技能修订与评估证据配对**（practice feedback）；
2. 结构化记录 **诊断 → 修订 → 证据 → 结果** 四段历史；
3. **角色分离的子代理**：一个在 practice probes 上跑候选技能，**脱敏汇报**；另一个据历史提修订；
4. 效果：不用预置搜索栈，GAIA **+15.8**、WebWalkerQA-EN **+3.2**；内部工具场景平均 **+18.8**。

### 对照我们现在的状态

| SkillHone 的要素 | 我们有吗 | 差距 |
|---|---|---|
| 只保留最终产物 = 反面教材 | ✅ 我们保留 `history[]`（内容 + 替换时间） | 但**只有"改成了什么"，没有"为什么改、依据什么、结果如何"** |
| 结构化决策历史（诊断/修订/证据/结果） | 🟡 部分：`evidence.status`、`supersedeReason`、审计日志 | 缺**诊断**与**结果**两个字段 |
| practice probes（候选先在历史回合上试跑） | ❌ 没有 | CPE 只做事后回归，**没有"准入前试跑"** |
| 角色分离 + 脱敏汇报 | 🟡 子代理有互斥路径规范 | 无"脱敏"要求（子代理报告可能带原文/隐私） |

### 三个可直接落地的升级（P4）

**P4-1 准则历史四段化**
`PlaybookEntry.history[]` 每条从 `{content, replacedAt}` 扩为
`{content, replacedAt, diagnosis, evidence, outcome}`。
- diagnosis：为什么改（一句话）
- evidence：依据哪条记忆/哪次会话（id 或链接）
- outcome：改了之后 helpful/harmful 怎么变
**验收**：改一条准则必须填 diagnosis；面板能看到"这次修订的依据"。

**P4-2 practice probes（准入前试跑）**
候选准则在被采纳前，用**最近 N 个真实回合**做影子试跑：
若"这条准则当时会被触发"且用户当时是纠正（appliedBad），记为反证；反证 ≥2 条 → 拒绝采纳并写明原因。
**验收**：构造一条与历史纠正冲突的候选 → 必须被拦下，且理由可读。
**注意**：这比 CPE 更前置（CPE 是"生效后回滚"，这是"生效前拦下"）。

**P4-3 子代理报告脱敏**
委派子代理写调研/复盘时，任务里明确"只写结论与可核对出处，不贴私人内容原文"。
**验收**：检查子代理产出里不含站名/人名/地块编号等敏感串（正则黑名单 + 人工抽查）。

### 不抄的部分

它是 **harness + 子代理编排 + 搜索栈**的规模，我们没有也不需要。它值钱的是**"决策历史"这个数据结构**，不是它的执行框架。

---

## 三、一句话结论

- **PyBot：不采纳**，只当"确定性路线可行"的旁证 + "别用 swarm 写代码"的反例。
- **SkillHone：采纳机制**。最该补的是**准则修订的决策历史（诊断/证据/结果）**和**准入前试跑**——这两条正好补上我们"准则只有结果、没有依据"的空档。
