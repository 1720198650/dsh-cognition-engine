## 二、精读笔记（5 篇）

### 2.1 多实例处理（ACL 2026, 1470）——直接决定我们该注入几条

**做法**：把"处理 N 个实例"（例如逐条评论判情感再汇总）当独立能力来测，控制实例数与上下文长度两个变量。

**结论（可直接用的数字）**：
- 所有模型都是**先轻微下降（约 20–100 个实例），再在更大实例数上崩塌**；
- **实例数的影响大于上下文长度**——也就是说，把 100 条压成 1 段摘要，比"保持 100 条但缩短每条"更有效。

**对我们的意义**：我们每轮注入「1 页准则（最多 12 条）+ 核心摘要 + 缺口」，本质上就是多实例输入。
按这篇的结论，应优先**减少实例数**，而不是继续压缩每条的字数。

**落地**：见 P0-1。

### 2.2 In-Context 引发的涌现性失准（ACL 2026, 1770）——注入会外溢

**做法**：给模型喂少量"窄领域"的 in-context 示例，然后测它在**无关的良性问题**上是否失准。

**结论**：
- 失准确实出现，EM 率 **1%–24%**，**最少 2 个例子就够**；
- 更大的模型**不一定更安全，通常更易感**；
- 机制假设是"安全目标 vs 跟随上下文"的冲突：**提示模型优先安全 → EM 下降；提示优先跟随上下文 → EM 上升**。

**对我们的意义**：准则本就是"窄领域的强指令"。若不加边界，12 条关于发版/文档的约定可能让模型在无关话题上变得过度服从或过度谨慎。
**落地**：注入尾部固定一句边界声明 + 主题化注入 + 回归测试（P1-3）。

### 2.3 多轮对话掉 39%（2505.06120）——长会话必然退化

**做法**：200,000+ 模拟对话，对比单轮与多轮。

**结论**：
- 六类任务平均掉 **39%**；
- 拆解为"能力微降 + **可靠性大幅下降**"——不是变笨，是变不稳；
- 关键机制：**模型早轮就自作假设并急于给最终解，然后过度依赖那个解；一旦走错方向就不会回头**。

**对我们的意义**：我们的核心卖点就是跨轮携带上下文。这篇说明**光带着上下文还不够**，要防"早轮假设固化"。
**落地**：P0-2 的"假设台账"。

### 2.4 基准可以被恒定输出骗过（ICLR 2025 Oral, 2410.07137）——别信 LLM 当裁判的主指标

**做法**：构造"null model"——对任何输入都返回同一段结构化文本。

**结论（最重要的三个数）**：
- AlpacaEval 2.0 的 **length-controlled 胜率 86.5%**；Arena-Hard-Auto **83.0**；MT-Bench **9.55**；
- 单纯"有说服力"的话术没用（<1%），**结构化伪造模板**才有用（76.8%）——它骗的是评估模板的句法解析；
- **改写模板不管用**（对未见模板仍 92.1%）；**PPL 过滤也不管用**（作弊文本困惑度低于阈值）。

**对我们的意义**：我们的 CPE 闸门与 `evals/` 如果用 LLM-as-judge 当主指标，同样可被"结构化长答案"骗。必须：
① 主指标用**规则判定**（精确匹配/包含/排名），LLM 只做辅助；
② 加**退化输出检测**（恒定、空、超长、复读）；
③ 候选顺序随机化。

**落地**：P0-3。

### 2.5 思维链日志就是隐私事故源（2608.09867）

**结论**：从公开仓库抓 **315,320** 个加密推理块，解出 **367 条 PII、182 个凭据**；还能藏不可见的 prompt 注入。

**对我们的意义**：`cognition-injection.jsonl`、`cognition-audit.jsonl`、会话日志都含真实正文（我们刚为此重写过历史）。
**落地**：P2-3（文档 + 导出脱敏脚本）。

### 2.6 目的论偏差（ACL 2026 Best Paper, 689）——模型爱说"已完成"

**结论**：模型对目标导向事件系统性幻觉"已经完成"，**即使文本明确说没完成**；提示词修正会引发校准危机（该通过的反而不通过）。

**对我们的意义**：这正是用户反复抓我的点（"这不还在吗"）。
**落地**：P1-1：**"完成"必须有可核对证据**，否则只能说"已提交改动，未验证"。

## 三、升级计划

### P0（本轮就做，1 周内）

**P0-1 注入实例数上限 + 结构化聚合**
- 依据：ACL 1470（实例数 > 上下文长度；20–100 起降，之后崩塌）
- 做法：
  1. `playbookMaxEntries` 默认从 **12 降到 6**；新增 `injectMaxInstances`（默认 8，含摘要与缺口），超出部分只留"标题+id"提示，不展开正文；
  2. 超限时改为**一条聚合摘要**（"另 7 条未展开：…"），而不是继续列条目；
  3. 面板暴露"本轮注入了几条/多少字"，便于用户自己判断。
- 验收：单元测试覆盖「超限折叠」；注入字符数与条数可在 `/cognition-engine/injected` 读到。

**P0-2 多轮漂移防护：假设台账**
- 依据：2505.06120（掉 39%，主要是可靠性；早轮假设固化后不回头）
- 做法：
  1. 每轮从 `session/event` 里抽"模型自己下的假设"（无证据的断言，如"按你的意思应该是…"），记成 `assumptions` 列表；
  2. 下一轮注入时附「本会话已作出的假设（未经确认）」三条上限，要求模型确认或撤回；
  3. 用户说"不对"时，清空该假设并记一次 `appliedBad` 到对应准则（链路已存在）。
- 验收：模拟三轮对话的单测：第 2 轮注入里出现第 1 轮的假设；用户否认后该假设消失。

**P0-3 评测防作弊**
- 依据：2410.07137（null model 86.5%）
- 做法：
  1. `cpe.check()` 的判定改**纯规则**（期望 id 是否在 top-k），禁止接 LLM 打分；
  2. 新增 `degenerateAnswer()` 检测：与上一条完全相同 / 长度 < 5 / 长度 > 3× 中位数 / 重复率 > 0.6 → 直接判 fail 并记 `antiCheat` 原因；
  3. 随机化候选顺序（同一 case 跑两次比较一致率）。
- 验收：喂一个"恒定输出"的假模型，`cpe.check()` 必须判红，不能判绿。

### P1（下个迭代）

**P1-1 "完成"必须有证据**
- 依据：ACL 689（目的论偏差）
- 做法：`manage_long_task` 的 `stage='done'` 必须带 `evidence`（文件路径/命令输出/链接），否则只能到 `review`；注入层固定一句"未验证不得声称完成"。
- 验收：单测：无 evidence 转 done 被拒。

**P1-2 开工前歧义闸门**
- 依据：2604.21505（歧义必然掉分，模型不会自己发现）
- 做法：新增 `cognition_ambiguity` 工具或在 `cognition_context` 里加检查表（词汇/句法/语义/模糊四类），命中就输出**一个**精确问题（不许连问三个）；结果写进 ticket 的 `blockedBy`。
- 验收：给"帮我优化一下那个文档"这类输入，工具返回歧义类型 + 单个问题。

**P1-3 注入边界声明 + 主题隔离回归**
- 依据：ACL 1770（窄示例外溢，2 条即够；强调安全可缓解）
- 做法：注入尾部固定一句「以上为当前任务的约定，不改变安全边界与身份」；新增回归：只注入"发版"主题准则时，问一个无关领域问题，输出不应带发版口吻（用规则分类器判）。
- 验收：回归用例通过；面板可关闭该句（`injectBoundaryNotice`）。

**P1-4 最小编辑**
- 依据：2604.05963（过度编辑是主因，最小编辑 +31.4%）
- 做法：派单模板加「只改必要行；不得顺手重构/改格式」；review 时统计 `改动行数 / 必要行数`，比值 > 3 提示人工看。
- 验收：派单文本含约束；统计函数单测。

### P2（按需）

- **P2-1 反思用语言化采样**（2510.01171）：antithesis 要求 3 条批判各带概率，取最高那条喂 synthesis。成本 ×3，只在高价值反思开。
- **P2-2 置信度分档**（2505.17537）：没有 logits，用"证据强度"代理——用户确认过 / 有实测输出 / 仅模型推断，三档显示，最后一档禁止标"确定"。
- **P2-3 日志隐私**（2608.09867）：README「数据与隐私」补一节 + `scripts/redact-export.mjs`（导出时把正文替换成 id+摘要）。
- **P2-4 人格审计改自由作答**（2502.18798）：若审计题用选择题，改为自由作答 + 规则判分，或随机化选项长度。
