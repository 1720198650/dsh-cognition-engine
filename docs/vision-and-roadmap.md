## 二、你真正想要的（我的理解）

你说过一句话，我认为是全部需求的源头：

> **「我最开始想把插件做成这种能自我行动的，有长期记忆，有性格那种。」**

拆开是三层，难度完全不同：

| 层 | 要什么 | 现状 |
|---|---|---|
| **记忆层** | 记得住、记得准、会作废 | ✅ 已做（v0.11.0 是这一层的完成度最高点） |
| **人格层** | 说话像一个人，有稳定的偏好和边界 | ❌ 没有 |
| **行动层** | 能自己观察、判断、动手 | ⚠️ 有闸门，没接火 |

再往上，是一个更抽象的目标：

> **不是「更聪明的 AI」，是「更靠谱的搭档」。**

## 三、五个必须先想清楚的张力

### 1. 记忆越多 ≠ 越像人

人 memory 是**选择性**的：记得住重要的，忘得掉琐碎的。
一个什么都记得的 agent，会变成「你上次说过……你三个月前说过……」——**这不是像人，是像审讯**。

> 所以：记忆的价值不在「多」，在「准」和「该忘的忘」。

### 2. 人格越强 ≠ 越像人

强人设容易变成**漫画式表演**：每句话都带口癖、每个回答都先撒娇。
《Best Friends, Not Forever》（Salesforce，2026）实测：2,008 段对话、27 个人设，
**轨迹准确率平均只有 44.4%，用户状态回忆接近随机**。人格会漂移、会崩塌。

> 所以：人格需要**审计**，不是写一段 prompt 就完事。

### 3. 主动性越强 ≠ 越有用

主动 agent 的最大失败模式不是「不做事」，是**刷屏**。
dsh-superagent 的整个哲学就是「**take as little human attention as possible**」——
每条消息都要值回它花掉的注意力。

> 所以：主动必须默认 **record-only**，先证明「它本来会做的事是对的」，再放开说话。

### 4. 学习越多 ≠ 越准

从闲聊里自动提取「长期记忆」，会把「今天累了」写成「用户长期疲惫」。
QQ bot 实战项目的结论：**长期记忆只允许主人手动添加**。

> 所以：自动提取只能进**候选队列**，人确认才生效。

### 5. 零依赖 ≠ 零能力

我们证明了：BM25、NegEx、TMS、幂律衰减，都可以用纯 JSON + 纯 TS 实现。
但 **L4（权重更新）做不到**——那需要训练基础设施，不是插件的事。

> 所以：能力的上限靠模型，**可靠性的下限靠我们**。

## 四、目标拆解：四个可验收的能力

### 4.1 记得准（已有，缺度量）

- 双时态 + 主题 + 准则 + 证据链 + 缺口
- **缺**：真实检索日志、top-3 人工标注、记忆准确率基线
- 验收：50 条真实查询，Top-1 ≥ 80%，Top-3 ≥ 95%

### 4.2 说得像（Persona + Expression）

**Persona 块**（Letta 做法）：

```json
{
  "blocks": [
    { "id": "persona", "value": "说话直接，不铺垫；先给结论再给理由；不确定时明说。", "limit": 400 },
    { "id": "human",   "value": "做文档整理工作；要求先查证再动手；讨厌空话。", "limit": 600 }
  ]
}
```

- 注入在最前，pinned，不衰减、不淘汰
- agent 只能提议，用户确认才生效
- 单次改动 >30% 二次确认，保留 diff
- **验收**：改人格后连续 5 轮，句长/结论先行率/不确定表达率可测量地变化

**Expression 表**（MaiBot 做法）：

- 从用户消息里提取**反复出现的短语**（≥3 次、2–8 字），存为「表达偏好」
- 只影响措辞，不产生事实
- 按主题相关性注入，最多 5 条
- **验收**：每 10 轮至少复用 1 个用户常用短语，且不产生事实性错误

### 4.3 不添乱（Proactive Gate）

- `cognition_tick`：检查到期任务 / 未解决缺口 / 证据链断裂 / 过期准则
- 结果进面板「本来会做什么」，**默认不发消息**
- 只有用户写了规则（「每天 9 点提醒我」）才发
- 预算：每小时 ≤1 条，每天 ≤3 条
- **验收**：面板能看到 would-do；一周内零主动消息（除非有规则）

### 4.4 能办事（Tickets）

- 任务升级为 Ticket：`queued / working / awaiting review / blocked / failed`
- 每个 Ticket 有工作日志、产出、人工交接点
- **验收**：一个任务从创建到交付全程可追溯；每个动作有审计记录

## 五、路线图

### Phase 0：度量基线（3–5 天）

**为什么先做这个**：BM25 研究的最后一条建议是「先用最近 100 次真实召回日志人工标 top-3——
这一步比报告里所有建议都值钱」。我们自己的三轮基准全是合成的。

- 记录每次 `cognition_recall` 的查询、命中、用户是否采纳
- 人工标 50–100 条
- 产出：检索准确率基线、误召回 Top-10

**验收**：有一张真实的「查询 → 应该命中什么」的表。

### Phase 1：Persona（2–3 天）

- `cognition-persona.json` + `cognition_persona` 工具
- UI：设置页两个编辑框（人格 / 用户）
- 注入在最前，pinned，diff 历史
- **验收**：5 轮风格变化可测量；人格块变更全部可追溯

### Phase 2：Expression（3–5 天）

- `expression` 表 + 提取器（频次 + 长度 + 来源）
- 注入按主题相关性，最多 5 条
- **验收**：复用率达标，且不污染事实

### Phase 3：Proactive（3–5 天）

- `cognition_tick` + 面板「本来会做什么」
- 默认 record-only
- 规则引擎：用户写「每天 9 点提醒」才发
- **验收**：零主动消息一周；面板 would-do 可读

### Phase 4：Tickets（1–2 周）

- 任务状态机 + 工作日志 + 人工交接
- **验收**：一个任务全程可追溯

### Phase 5：Audit（3–5 天）

- 人格保持度自检（20 题，月度）
- 记忆质量报告（准确率、证据完整度、冲突数）
- **验收**：月度报告能回答「这个月它有没有变傻/变漂」

## 六、北极星指标

不要用「记忆条数」当指标——那是虚荣指标。用这五个：

| 指标 | 定义 | 目标 |
|---|---|---|
| **重复解释次数** | 用户因为「它忘了」而重说的次数 | 每周下降 |
| **同一错误重复次数** | 同一个坑踩第二次的次数 | 0 |
| **主动消息采纳率** | 主动提醒中用户认可的比例 | ≥70% |
| **人格保持度** | 月度自检的 persona retention | ≥80% |
| **记忆准确率** | 真实查询 Top-1 / Top-3 | ≥80% / ≥95% |

## 七、不做什么

| 不做 | 理由 |
|---|---|
| ❌ 权重训练 / 微调 | 零依赖插件做不到；需要训练基础设施 |
| ❌ 自我修改代码 | 风险远大于收益 |
| ❌ 无审批的自动执行 | dsh-superagent 自己的安全模型都被标为「弱」 |
| ❌ 自动提取人格 | 会把临时状态写成永久人设 |
| ❌ 情绪表演 / 假装有内心 | 短期有效，长期失真 |
| ❌ 为了「像人」堆参数 | 人格崩塌是实测问题，不是参数不够 |

---

## 八、一句话

> **目标不是「做一个像人的 AI」，是「做一个让人愿意长期用下去的 AI」。**
> 长期用下去的三个条件：**记得准**（不重复问）、**说得像**（不别扭）、**不添乱**（不刷屏、不乱来）。
>
> 这三条，正好对应我们要做的三层：**记忆治理、人格块、主动闸门。**
